The embedded dispatcher runs one dispatch_once per board on EVERY tick and
enumerates the board root dynamically. A newly created board is therefore
picked up on the next tick — there is no opt-out list.

=> CEO assumption #1 / risk mitigation "Slot-Test nur auf slot-test, dessen
   Pfad das Gateway nicht kennt" does NOT hold for boards: the DB file is
   unknown to the gateway, but the board DIRECTORY is enumerated.

Mitigation used for the clean run (no gateway stop, no production config edit):
set "archived": true in slot-test/board.json. list_boards(include_archived=
False) then skips the board, while an explicit `--board slot-test` (slot and
rollback dispatcher) still resolves its directory. Evidence: board.json in
this directory listing / config-source section.

Consequence for production roll-out: switching `kanban.worker_mode` to
persistent in ONE profile's config only idles the gateway dispatcher when the
gateway boots with that config. With worker_mode=persistent the whole gateway
stops dispatching for ALL boards (the watcher returns early), so a test board
is safe in that mode — but in dispatcher mode there is no per-board isolation.
